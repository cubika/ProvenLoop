# ProvenLoop 0.1.0-alpha.0.8

**Date:** 2026-09-06
**Channel:** Windows Design Partner Preview — evidence candidate

This candidate follows `0.1.0-alpha.0.7`. It is not a quality-approved Alpha:
**M0/MVP remain No-Go**, controlled field benefit is not established, and
`0.1.0-alpha.1` remains an unapproved quality-release target.

## Install

```powershell
irm https://raw.githubusercontent.com/cubika/ProvenLoop/v0.1.0-alpha.0.8/install.ps1 | iex
```

The installer verifies the GitHub Release tarball's SHA-256 checksum and uses
npm only as a local installer. This candidate is not being published to the
public npm registry. See [installation and operations](../alpha-installation.md)
for prerequisites, opt-outs, upgrade, and rollback.

## Changes

- Native SDK causal verification bridge and `assistant.turn_start` mapping.
  Correction proof is bound to the operation, repository, and worktree;
  old confirmations cannot erase newer counterevidence.
- Trusted live SDK Session registry with a cross-process reader-probe guard
  and explicit real-user approval for persistent MCP feedback.
- Natural English/Chinese retrieval and corrected exclusion matching.
  Task-start instructions request relevant context without guaranteeing host use.
- Knowledge list/show/confirm/replace/revoke with reviewed digests and explicit
  confirmation. Workflow controls require a matching live `SESSION_ID`,
  workflow, and cwd; flags alone do not authorize access.
- Automatic local observation summaries and privacy-minimized exports that
  separate context exposure, explicitly reported adoption, and unknown outcomes.
- Bounded current-session reconciliation wired into the installed Extension's
  background loop. It strictly matches SDK `sessionId`/`workspacePath`, validates
  state/path/lease boundaries, and excludes pre-join records. Worker/admission
  runs first, then reconciliation and observations every 30 seconds; actual
  progress or budget exhaustion schedules two-second catch-up. Shutdown stops
  the loop.
- Two-pass capture-metadata redaction, append-only enrichment, corrupt-queue
  isolation, acknowledged-item pruning, transactional deletion, restore
  tombstone checks, and schema-10 maintenance with pre-upgrade snapshots.

## Upgrade and known limitations

- Upgrade from the previous 0.7 candidate with the versioned installer above.
  Keep recovery snapshots and the prior runtime slot. Integration rollback does
  not make an older runtime compatible with schema 10; there is no public
  restore CLI. Preserve deletion tombstones during maintainer-assisted recovery.
- Missing or mismatched SDK workspace metadata produces a diagnostic and skips
  automatic backfill. Capture is best effort, not lossless archival or full
  historical ingestion; reconciliation is bounded to the current observation
  window and supported accessible records.
- Pending/dead-letter queue data has no total storage quota. Acknowledged-item
  pruning does not limit backlog when the worker is paused.
- Windows/platform, paired latency, provider-degradation, native-host recovery,
  and two-version remote-upgrade acceptance still require retained evidence.
- Synthetic fixtures, local observations, and maintainer attestations cannot
  clear `field-effect-evidence`. Exposure is not adoption, helpful feedback is
  not verified success, and unknown safety/outcome counts are not zero.
- Release automation checks the versioned build and installed tarball. Those
  checks do not constitute retained native-host acceptance or controlled
  field-benefit evidence.
