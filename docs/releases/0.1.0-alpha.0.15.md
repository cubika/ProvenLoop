# ProvenLoop 0.1.0-alpha.0.15

Date: 2026-09-11. Channel: Windows Design Partner Preview.

This preview filters temporary instructions from learning, distinguishes source
references from verified recovery rules, and adds local knowledge management.
It also provides explicit record cleanup while preserving installation and
configuration. M0/MVP remain No-Go for quality release; controlled benefit and
actual model extraction quality have not been established.

## Install or upgrade

```powershell
irm https://raw.githubusercontent.com/cubika/ProvenLoop/v0.1.0-alpha.0.15/install.ps1 | iex
provenloop learning status
provenloop ui
```

The installer verifies the exact GitHub Release tarball and SHA-256 sidecar.
This preview is distributed through GitHub Releases without public npm publication.
Retain the prior runtime and a compatible recovery snapshot before upgrading.

Canonical storage advances to schema 16 from schema 14 in versions 0.12 through
0.14. Use the normal maintenance upgrade path; opening the viewer does not
migrate storage. Older runtimes cannot read schema 16.

## Learning and scope

Background learning is enabled when installation, capture, worker, and correction
learning are enabled. An explicit `provenloop learning disable` remains effective
across upgrades, restarts, and capability changes. Older installations without
a recorded learning preference use the new default. Background requests send
bounded, redacted excerpts to Copilot using the existing sign-in and service quota.
Repository hook approval remains a separate permission.

The learner checks future usefulness, duration, and source scope before retaining
new proposals. Temporary session instructions and completed setup edits are
rejected. Untyped findings finish evaluation instead of waiting indefinitely
for an execution proof they cannot supply.

Qualified conventions may return exact user wording. Qualified references may
return captured tool excerpts in the matching worktree and revision. Both keep
their `inferred` label; neither fabricates external verification. These paths
preserve useful source material, but do not establish that the model has derived
a broader reusable principle. Automatic activation still requires a supported
recovery proof. Legacy candidates require review.

Repository mismatches remain unresolved rather than inheriting the launch
directory as authority. Task-local constraints stay within their originating
session and are excluded from unrelated sessions on the same branch. Similar
rules in the same verified scope are suggested for review, without automatic
merging of records or evidence.

## Work episodes and local controls

Work episodes use bounded goals with source references. Runtime-only and internal
summary traffic are excluded. Last activity and session closure are displayed
separately; neither is evidence that the task succeeded.

`provenloop ui` now supports adopting a rule, editing its content or scope,
archiving it, and deleting it. Adoption and editing create a distinct
user-confirmed rule and preserve the original through supersession. Evidence
pages stay read only. Write forms require same-origin requests, CSRF tokens,
explicit confirmation, and a current review digest where applicable.

Overview separates cumulative captured events from recent ingestion growth and
queue backlog. It shows event, session, trust, and adapter-version distributions,
alongside database sizes for the selected data root. A high event count alone
does not establish useful learning or a capture defect.

## Record cleanup

For selective cleanup, `provenloop capture retention plan` proposes old closed
sessions using a 90-day review window. It protects retained evidence dependencies,
recent activity, incomplete capture, and unfinished learning. Applying a plan
requires its exact cutoff and digest, selected session IDs, and confirmation.
New queued activity prevents a reviewed session from being removed. No background
age-based deletion is enabled.

To start with no records, expand **Clear all records** on Overview, type `CLEAR`,
and select the confirmation checkbox. The CLI equivalent is:

```powershell
provenloop records clear
provenloop records clear --confirm
```

The first command previews the selected data location and counts. Confirmation
clears events, knowledge, episodes, learning jobs, usage, queues, indexes, record
artifacts, and owned database recovery snapshots. Installation, capability
settings, plugin/configuration backups, repository files, and Copilot
conversation history remain in place. This action cannot be undone through
ProvenLoop.

The reset stops ProvenLoop extension activity and drains storage users. Restart
Copilot afterward to collect new records with the same settings. A retained
cutoff blocks reimport of old events. If cleanup is interrupted, records and
capture remain unavailable until the same clear action completes.

## Validation and remaining limits

Regression tests cover retention decisions, source qualification, repository and
session isolation, episode quality, UI request controls, stale reviews, projection
updates, deletion propagation, and reset recovery. Local tests exercised the real
HTTP server and reset service against disposable installations, verified empty
record tables, and checked that configuration remained unchanged. These checks
do not measure model extraction quality or developer productivity.

The release process will run lint, type checking, unit and integration suites,
packed-artifact verification, and the Windows PowerShell installer dry run.
Version-specific CI results and downloaded-asset checks must be recorded from
that process; no new CI run, commit, or artifact digest is claimed here.

Local checks on 2026-09-11 passed lint, type checking, all 273 integration tests,
and the Windows PowerShell 5.1 installer dry run for version 0.15. The full unit
run passed 1,050 tests; two native process tests were blocked by sandbox process
enumeration. Rerunning their two suites outside the sandbox passed all 63 tests.
No test assertion was relaxed or skipped for publication.

A working model host was unavailable for a fresh extraction-quality check. The
browser automation service was also unavailable for the final click-through
reset smoke test; HTTP and storage tests cover that path locally. Reported
historical records were not automatically rewritten, merged, or deleted.

M0 platform, latency, provider-degradation, remote-upgrade, and controlled-effect
evidence remain separate requirements. `0.1.0-alpha.1` remains an unapproved
quality-release target. See the [viewer guide](../local-viewer.md),
[installation guide](../alpha-installation.md), and [feedback record](../feedback.md).
